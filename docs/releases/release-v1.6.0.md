## v1.6.0

Clawd v1.6.0 adds Windows computers as Remote SSH hosts, supports the Kiro IDE, and reminds you when Copilot CLI or Claude Desktop is waiting for your answer. The pet uses far less CPU when it is hidden, on scaled displays and while wearing accessories, and it can play small idle animations. Phones can pair by scanning a QR code, and the Windows installer, hooks and update flow got several fixes.

### Remote SSH

- **Windows remote hosts** (#1319, #1320, #1324, #1331; issue #1316) — Clawd on macOS or Linux can now deploy to a Windows computer over SSH, so Claude Code, Copilot, Codex and the DeepSeek Harness desktop app running there report back to your local pet. Deploy, Repair and Uninstall work the same way as for other hosts, and only Clawd's own entries are touched. Limits: only the default (account-default) setup is supported; a Windows host has no Codex log fallback monitor, no Hermes and no status-line quota; DeepSeek Harness needs the same user to be signed in on that computer's desktop, and its desktop app must be restarted after the Clawd plugin changes. Linux and macOS remote hosts deploy exactly as before. Before merge, real Windows hosts covered DeepSeek Harness and Codex MCP approval round trips; a Codex CLI Bash/apply_patch approval round trip on a Windows host was not tested. Thanks to @Ken0221 for the report.
- **Remote MCP approvals follow automation** (#1337) — when Codex uses the default way of handling approvals, ordinary plugin (MCP) tool requests from a remote computer (Remote SSH or WSL) are now answered the same way as other requests that your "Permission request handling" setting would allow immediately. This overrides a plugin's own "ask every time" setting on that computer. Codex's built-in apps (`codex_apps`) are excluded, and so are local MCP requests, session overrides and held requests. When Clawd cannot answer, the request goes back to Codex on that computer; for Remote SSH requests, macOS also shows a read-only reminder with only a "Got it" button (WSL and local requests keep the usual pet cue). Related: #1186.

### Agent integrations

- **Kiro IDE** (#1339) — the Kiro desktop app drives the pet through a global hook in `~/.kiro/hooks/`, and appears as its own card in Settings → AI Coding Tools, separate from Kiro CLI (install it there). When Kiro waits for you to confirm something, Clawd shows a read-only reminder card with "Go to Kiro" and "Got it"; Kiro does not let a hook approve for you, so you answer inside Kiro and the card folds away. The card can be turned off with "Show a reminder when confirmation is needed". Kiro runs hooks only in trusted workspaces. Tested only on macOS (Kiro 1.4.86); Windows and Linux are not tested.
- **Copilot CLI waiting for you** (#1343, #1344) — when Copilot waits in the terminal for you to approve a path outside the workspace, confirm a web fetch or answer an `ask_user` question, the pet stays in its waiting pose and the HUD row shows the approval badge until you answer. Copilot does not let a hook approve these, so Clawd only reminds you to go back to the terminal. A command approval still alerts once. If you deny or press Esc, the pet keeps waiting until you send your next message (at most about two hours). Remote SSH Copilot is supported. The Copilot card has a new switch, "Alert me when it waits for input". Kiro no longer rings every few seconds while it waits for you.
- **Claude Desktop questions** (#1327, #1328; issue #1326) — when the Code tab of Claude Desktop ends a turn with a question (the next-step question box), the pet shows a read-only card with the question and the button texts, and the session row is marked as waiting. You answer in Claude Desktop; clicking the card only brings Claude to the front without opening the exact session, and for a remote session the click only closes the card. The card does not change the pet's state and makes no sound. A new setting, Settings → Notifications → "Remind me about unanswered Claude questions" (off by default; "Remind after" 1 to 120 minutes, default 5), shows the card again with a sound if the question is still unanswered, once per question. Tested only on macOS. Thanks to @Yike-Ye.
- **Codex settings** (#1338) — AI Coding Tools → Codex no longer asks you to pick between Auto and Intercept. The Approvals group is now one explanatory line, and "Send every approval to Clawd" under Advanced replaces the old Intercept choice: on means what Intercept meant. Existing settings keep their meaning.
- **Codex titles** (#1253, #1314; related #1254) — Codex Desktop threads that only exist to refresh a title no longer show up as HUD rows, and late events from an ended internal thread no longer bring one back. Ordinary side chats and other titles still show. Thanks to @200780381.
- **Antigravity on Windows** (#1271) — the Antigravity CLI status-line script now runs: the command used to carry quotes that `agy` could not find the script through. Install paths with Chinese user names work too. Thanks to @YOIMIYA66.

### Pet

- **Hidden pet costs far less** (#1300, #1301, #1304; related #1303, #1305) — while the pet is hidden (manually, by full-screen auto-hide or by the system) it no longer paints animations, walks or runs accessory loops. On Mac the CPU drops by about 90%; on a Windows high-refresh screen by about 40%, and with a hat or cigarette worn from about 12% to about 1%. When shown again the pet is where it was and free roam waits 8 seconds before it starts.
- **Lower CPU at common display scales** (#1303) — at screen scales other than 100% (including Retina and a changed Windows text size), the Clawd theme's animations no longer take the main thread on every refresh: in testing on a Windows high-refresh screen with the Clawd theme and no accessories, the CPU was about halved while shown and close to zero while hidden. A few unusual scale combinations (for example 225% display scale with 110% text size) still use the old path; accessories got their own savings below.
- **Cheaper accessories** (#1305) — wearing a hat or cigarette cuts the CPU a lot: on a Windows high-refresh screen from 33–44% with both worn to 11–14%. Smoke now updates 12 times a second and the hat follows the pet's animation rhythm. Taking the cigarette off also stops its background animation, which used to keep running.
- **Idle activities** (#1302, #1309; issue #1252) — Settings → Pet → "When idle" now offers one of "Stay put", "Free roam" and "Idle activities". The default is "Stay put", and a profile that already used free roam keeps it. With "Idle activities", while no AI tool is working, the pet occasionally plays another animation from the theme (thinking, typing, juggling, sweeping, happy, carrying); "How often" can be Rarely, Sometimes or Often. Clicking or dragging the pet, or a new task, makes it stop at once. Thanks to @hanzhe-one, and to @cuentasdecorreodediego-code for the request.
- **Eye tracking switch** (#1285, #1312; issue #1276) — Settings → Pet → "Follow the mouse cursor": turn it off and the idle eyes stay looking forward (Cloudling too), effective immediately; turning it on again restores the cursor direction. The spin-the-pet-dizzy easter egg still works. Thanks to @xiaoshidefeng, and to @PGTea for the request.
- **Keep the pet on top** (#1287; issue #1275) — a new switch, "Keep the pet on top of other windows": turn it off to let other windows cover the pet. On macOS it takes effect after a restart, and the pet and the session HUD hide while a native full-screen app is in front (see Upgrade Notes). "Auto-hide in fullscreen" now works on macOS as well. Thanks to @xiaoshidefeng, and to @framefutura for the request.
- **Right-click while dragging** (#1265; issue #1260) — a right-click during a drag no longer freezes the pet and leaves clicks passing through to the desktop. Thanks to @xiaoshidefeng, and to @qxii2027 for the report.

### Phone pairing

- **Scan to pair** (#1315; issue #1299) — Settings → Permissions & approval → LAN approval now shows a QR code next to the pairing link; scan it with the phone camera instead of typing the 8-character code. It was tested on an iPhone and an Android phone. A Home Screen app on iOS opens Safari when it scans. Thanks to @xiaoshidefeng.
- **Phone page follows your language** (#1322) — the LAN page shows in the language chosen on the computer (all seven interface languages); refresh the page on the phone after changing it. Thanks to @xiaoshidefeng.
- **Home Screen apps and the root address** (#1321, #1345) — an app added to the Home Screen shows as "· PWA" in the paired devices list so it can be told from Safari, and opening just the computer's address and port now goes to the phone page instead of a blank page. Renaming a device no longer breaks the connection if the new name cannot be saved. Thanks to @xiaoshidefeng.
- **Expired pairing codes** (#1332) — if the file cannot be written when an expired code is replaced, the LAN card no longer stays on "Unable to load connection info."; it still shows a fresh code and the reason is written to the diagnostics log.

### Windows

- **Update no longer says Clawd cannot be closed** (#1341; issue #882) — the installer sometimes missed a single remaining Clawd process, so it did not close it and could not move the old files, and a "Clawd on Desk cannot be closed" message appeared although Clawd had already quit. It now closes that process and goes on. This takes effect on the upgrade from v1.5.0 to this version. The original ARM64 report in #882 has another cause that is still being looked into. Thanks to @moc033702-svg and @PeterShanxin for the reports.
- **Faster Claude Code hooks** (#1297; issue #1293) — when Clawd detects Claude Code 2.1.160 or later and an absolute Node `.exe` path, Claude Code hooks start Node directly instead of going through PowerShell: an event arrives in about 84 ms instead of about 287 ms, and in hosts without a terminal (simulating Claude Desktop) in about 85 ms instead of about 890 ms. Older Claude Code versions and computers with Grok Build keep the PowerShell path, an unknown version keeps the existing hook form, and Claude hooks imported into Cursor no longer report; enable the Cursor integration to follow Cursor. Thanks to @trvny.
- **Upgrades keep your hooks** (#1298; issue #1293) — upgrading Clawd no longer removes the hooks of your AI tools; only a real uninstall does. See Upgrade Notes for this one-time upgrade.
- **Pet windows can no longer be closed from outside** (#1340; issue #1335) — if another program (for example a window manager) closed the pet window, it could not be brought back and starting Clawd again showed a main-process error. The two pet windows now ignore outside close requests; use Hide or Quit from the tray or the right-click menu. Thanks to @huiya07.
- **Screenshots** (#1294; issue #1282) — with the system snipping tool (Win+Shift+S) the pet is no longer raised above the capture overlay, so pressing on it does not drag the pet, and it does not walk during a capture. Other screenshot tools are not covered yet. Thanks to @05115120.

### Updates

- **A downloaded update stays ready** (#1296, #1311) — after a download finishes, if the bubble closes by itself or you choose "Later", the tray keeps "Update Ready", and opening it from the tray or About shows the install choice at once without checking or downloading again. After an error while preparing the install, trying again checks again (the same version reuses the downloaded package). Thanks to @200780381.

### Settings

- **Hints and scrolling** (#1256, #1317) — the (i) explanations now open in an in-page tooltip, the IM channels and LAN approval pages no longer jump to the top when you flip a switch, and the Footprints "This year" page loads, refreshes and scrolls more smoothly. Thanks to @YOIMIYA66.
- **Theme start-up** (#1306, #1307; issue #1295) — if the theme file cannot be read at startup, Clawd waits and tries again (a single read waits up to about 1.85 seconds, and your theme and the built-in fallback each have their own budget); if it still fails, the error now names the real cause. This addresses `Default theme 'clawd' not found` after an update on Windows. The trigger was not confirmed; if it happens again, the error now includes `ENOENT` or `EBUSY`. Thanks to @xiaoshidefeng, and to @200780381 for the report.

### Upgrade Notes

- **Remote hosts:** open Settings → SSH Hosts and run "Deploy / Repair Hooks" again on each existing host to get this version's Copilot and Codex hooks. Review the new Codex hooks in `/hooks` on the remote computer, and exit and resume any Copilot session that is already running so it loads the new hook.
- **DeepSeek Harness:** after Clawd refreshes the plugin, restart the DeepSeek Harness desktop app (and `dsh web`); Settings → AI Coding Tools shows a notice when a restart is needed.
- **Windows, from v1.5.0:** the v1.5.0 uninstaller still runs during this one upgrade and clears your AI tools' hooks once. Clawd restores the hooks of every integration that is installed and enabled when it starts; an integration you turned off is not written back, and if you turned off Claude Code's "Manage hooks automatically" you must repair it yourself. After this version, upgrades keep the hooks. Returning to v1.5.0 or earlier may duplicate hooks; upgrading again merges them. If that Windows computer is also a Remote SSH host for another computer's Clawd, this one-time cleanup removes the remote hooks as well, and starting Clawd there takes the hooks back for local use; quit Clawd on that computer and run Deploy / Repair Hooks again from the other computer.
- **Windows installer:** the fix for the "cannot be closed" message applies to the upgrade from v1.5.0 to this version.
- **macOS, "Keep the pet on top of other windows" off:** the setting takes effect after a restart, and while a native full-screen app is in front the pet and the session HUD hide even when "Auto-hide in fullscreen" is off (that row still shows off). Permission bubbles still appear.
- **Theme start-up:** the retry waits are not a fixed 1.9 seconds: one read waits up to about 1.85 seconds, and your theme and the built-in fallback each have their own budget, so a double failure can take longer.
- **Phones:** after changing the computer's language, refresh the phone page. A Safari tab and a Home Screen app still pair separately.
- **Downgrading:** the prefs schema remains version 21. Saving settings in v1.5.0 drops `eyeTrackingEnabled`, `petAlwaysOnTop`, `idleActivities`, `idleActivityFrequency`, `claudeTurnAskReminder` and `claudeTurnAskReminderMinutes` (Follow the mouse cursor, Keep the pet on top of other windows, When idle, How often, Remind me about unanswered Claude questions and Remind after), so they are back at their defaults after you upgrade again. The Codex approval choice is kept. v1.5.0 has no Kiro IDE support. Back up prefs before downgrading.

### Known limitations

- **Remote SSH, third-party approval hooks:** if the remote Claude Code settings contain another local HTTP approval hook (pointing at `127.0.0.1`) listed before Clawd's own, Deploy / Repair Hooks reports a verification failure. Your other hook is not changed. Move it after Clawd's entry or remove it, then deploy again; a later version will fix the check. See [known limitations](https://github.com/rullerzhou-afk/clawd-on-desk/blob/main/docs/guides/known-limitations.md).
- **Platforms tested:** the Claude Desktop question card and Kiro IDE were tested only on macOS. Windows screenshot support covers only the system snipping tool.

### Validation Status

Validated with the v1.6.0 draft packages on 2026-11-08:

- **macOS (arm64, Apple silicon):** the DMG matches the draft digest and `latest-mac.yml`; the app is Developer ID signed, notarized and stapled (`spctl` accepted) and reports 1.6.0. Installed over v1.5.0, it starts in about 4 seconds, keeps settings, points the Claude Code, Kiro IDE and Copilot hooks at the installed app, leaves the Codex, OpenCode and WorkBuddy configs byte-identical, and receives real Claude Code and Codex events.
- **Windows (x64, Windows 11):** a silent upgrade from v1.5.0 finished in about 22 seconds and updated the same machine-wide installation to 1.6.0. As expected, the v1.5.0 uninstaller cleared the AI tools' hooks during this upgrade; after Clawd was started on the desktop, it restored the Claude Code, Codex, Copilot, Gemini CLI, Kimi and Qwen Code hooks (Gemini, Kimi and Qwen byte-identical to before the upgrade; Claude Code kept the PowerShell form because Grok Build is installed). With Clawd running, a Windows restart from the Start menu completed without any "preventing shutdown" prompt.
- **CI:** the tag build ran the full test suite on Windows, macOS and Linux, the native package audits for all five packages and macOS notarization; one Windows test timed out once under load and passed on rerun.

**Not tested** with the draft packages: the macOS x64 DMG; Linux packages on a real desktop (CI covers the X11/XWayland/AppImage smoke); Windows arm64; Remote SSH and Windows remote hosts end to end (a Codex CLI Bash/apply_patch approval round trip on a Windows host was never tested); Kiro IDE on Windows and Linux; the Claude Desktop question card on Windows; QR scanning on real phones (tested on an iPhone and an Android phone before merge). The in-app update from v1.5.0 to v1.6.0 and the APT source update can only be checked after publishing.
