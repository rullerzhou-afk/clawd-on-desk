# Codex + WSL: paths, Node, and pairing

Official sources checked: **2026-09-05**. Clawd source baseline: **`7383e8b80b8c0f05bd1dc53cb9e51fb96558a2ed`**. English source updated: **2026-09-05**. These dates are documentation/source checks, not a new device-validation date.

## Current support

OpenAI supports Codex in **WSL2**. Since Codex 0.115, WSL1 is no longer supported. Current Codex hooks are enabled by default; `hooks` is the canonical feature key and `codex_hooks` is a deprecated alias. Hooks that are not managed by policy still require review/trust through Codex's `/hooks` flow. See the official [WSL guide](https://learn.chatgpt.com/docs/windows/wsl) and [hooks guide](https://learn.chatgpt.com/docs/hooks#turn-hooks-off).

Windows Clawd provides an explicit **WSL Scan → Pair** flow. It does not silently install into every distro at startup or automatically poll sessions under a separate Linux home. Clawd uses Codex official hooks as its primary integration, with JSONL polling as a fallback for the configured session source. Codex's WSL support and Clawd's access to a particular home are separate questions.

## Configuration and execution paths

Windows and WSL use separate Codex homes by default. You can explicitly share Windows config, auth, and sessions by setting `CODEX_HOME=/mnt/c/Users/<windows-user>/.codex` inside WSL; see OpenAI's [shared-home instructions](https://learn.chatgpt.com/docs/windows/windows-app#share-config-auth-and-sessions-with-wsl). Sharing a directory does not determine which Node executable runs Clawd's hooks.

| Configuration | Hook execution | Network requirement |
| --- | --- | --- |
| Separate Linux home (`~/.codex` in WSL), integration installed in that distro | Linux Node | Linux must reach Windows Clawd's loopback listener; WSL2 normally needs mirrored networking. |
| Shared Windows `CODEX_HOME`, POSIX interop launcher generated by Windows | Windows `node.exe` through WSL interop | Uses Windows loopback, so this transport does not require mirrored networking, including under NAT. |
| Shared Windows `CODEX_HOME`, existing native POSIX launcher owned by the WSL/Linux installer | Linux Node; Windows synchronization preserves that launcher | Still uses the Linux network path. Shared home alone does not make this Windows interop. |

The second and third rows are distinct ownership branches in [codex-install-utils.js](../../hooks/codex-install-utils.js), covered by [codex-install.test.js](../../test/codex-install.test.js). Check the registered launcher and actual Node target before diagnosing networking; a `CODEX_HOME` value alone is insufficient. This source/test evidence does not claim that every shared-home combination has been tested on a device.

## Recommended: separate home and Pair

1. Install Codex and Linux Node in the intended WSL2 distro, and run Codex there to establish its own home.
2. Start Clawd on Windows. Open **Settings → Agents → Connected → WSL Scan**, find that distro under Codex, and choose **Pair**. The row may appear under **Unavailable** when Windows-local Codex is absent.
3. Confirm Codex is **enabled** in Clawd. WSL pairing is separate from installing the Windows-local integration and does not generally enable a disabled agent.
4. Check both installation and connectivity results, review/trust hooks in Codex as needed, then start a new session and confirm it appears in Clawd. A failed or unknown connectivity probe is not a connection success.

See the [WSL setup guide](setup-guide.md#wsl-windows-subsystem-for-linux) for manual installation from a full checkout, complete hook-file copying, and network troubleshooting. Do not use a hand-picked subset of `hooks/*.js`.

For Linux Node, Windows Clawd listens on `127.0.0.1:23333-23337`. WSL2's default NAT does not expose that Windows loopback listener to Linux. Mirrored networking requires Windows 11 22H2 or later; see [Microsoft's networking guide](https://learn.microsoft.com/en-us/windows/wsl/networking#mirrored-mode-networking). WSL1's shared loopback is a general networking fact, not support for modern Codex on WSL1. A network probe also does not validate every agent's permission transport; the setup guide describes Claude's separate, install-time permission URL limitation.

## Session discovery and verification limits

Pair installs hooks in the selected distro. It does **not** cause Windows' JSONL fallback to start polling every `/home/<user>/.codex/sessions` directory. Sharing `CODEX_HOME` can expose the shared session files, but it does not mount or discover other Linux homes. Startup synchronization of configured local integrations and user-initiated WSL pairing are different operations.

The remote Codex monitor is an architectural fallback for managed Remote SSH. It is not a new manual WSL scanner recipe. Secure Remote SSH requires its deployed identity and pinned transport; use [Settings → Remote SSH](guide-remote-ssh.md), not a standalone scanner detached from that layout.
